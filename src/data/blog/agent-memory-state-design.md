“把聊天历史全部塞回模型”不是完整的记忆设计。历史记录、当前任务状态和长期用户偏好，回答的是不同问题：刚才说了什么、任务执行到了哪里、跨会话应该记住什么。

假设用户先说“去杭州，预算三千”，下一轮补充“带老人，尽量少走路”。当前任务要保留城市与预算；执行器要知道哪些交通查询已经完成；长期档案却不能因此认定用户每次旅行都带老人。信息出现过，不代表应该永久保存。

## 三种数据，三个生命周期

| 层次 | 典型内容 | 读取方式 | 更新与失效 |
| --- | --- | --- | --- |
| 对话上下文 | 最近消息、引用、摘要 | 构建本轮模型输入 | 按上下文预算裁剪 |
| 任务状态 | 目标、步骤、工具结果、重试次数 | 执行器精确读取 | 随任务推进保存检查点 |
| 长期记忆 | 用户确认的偏好、可复用经验 | 按用户与主题读取 | 支持覆盖、过期与删除 |

“短期”描述作用范围，不等于“只能放内存”。例如 LangGraph 的短期记忆属于线程范围状态，可以通过 checkpointer 持久化；长期记忆则可以按自定义 namespace 跨会话读取。[官方记忆概念说明](https://docs.langchain.com/oss/python/concepts/memory)

如果进程重启后还要恢复任务，关键步骤就需要持久化。否则模型再聪明，也不知道某次工具调用是否已经完成。

## 任务状态不要只藏在自然语言摘要里

模型摘要可能漏掉否定词、日期或预算范围。对执行有影响的信息应使用结构化字段，摘要负责解释来龙去脉，而不是担任唯一事实源。

下面是虚构的状态示例，不是某个框架的配置格式：

```json
{
  "task_id": "trip-demo",
  "constraints": {
    "city": "杭州",
    "budget_cny": 3000,
    "prefer_less_walking": true
  },
  "steps": {
    "route_search": "completed",
    "availability_check": "pending"
  },
  "version": 3
}
```

工具结果还应有来源、查询时间、错误类型与稳定的调用标识。价格和余票有时效性，不宜作为长期不变事实。恢复任务时应先判断结果是否仍有效，再决定重查。

对于有副作用的工具，仅保存 `completed` 还不够。业务结果标识、幂等键与检查点更新顺序，决定了异常恢复会不会重复执行。这是执行一致性问题，不应该交给模型自由判断。

## 哪些内容值得写入长期记忆

我会先问：这条信息在未来是否仍有用，用户是否明确表达，是否能够更正，以及保存它是否合适。

一条偏好至少应保留以下元数据：

- 所属用户与记忆类型，避免不同用户串联。
- 信息内容与适用范围，例如“本次旅行”或“长期偏好”。
- 来源与确认方式，区分用户声明和模型推断。
- 更新时间、版本与必要的过期时间。

模型推断“用户可能不喜欢登山”，不能与用户明确声明“不安排登山”拥有同等事实地位。对于影响后续决策的推断，优先确认，或者仅作为本轮候选假设。

经验记录也不能自动升级为规则。一次工具失败可能来自临时网络故障，不足以证明这个工具永远不能使用。可复用经验需要保留当时条件与失败原因。

## 上下文压缩要保留什么

我会优先保留当前目标、硬约束、未完成问题、最近有效的工具证据，以及不能重复执行的动作记录。闲聊和重复日志可以压缩，但完整工具调用与对应结果不能被裁成互相脱节的消息。

```text
原始会话与工具记录
        ↓
结构化任务状态：用于执行和恢复
        ↓
近期消息 + 经核对的摘要 + 有限长期偏好
        ↓
本轮模型上下文
```

摘要最好带上生成所依据的消息范围。遇到新信息冲突时，可以定位原始记录，而不是围绕上一份摘要继续压缩，最终把失真层层放大。

更长的上下文窗口只是提高容量上限，并不保证模型会正确利用所有内容。仍应控制无关资料，记录 token 预算，并观察长任务中的约束丢失。

## 读取、隔离和删除同样重要

长期记忆不等于向量库。预算、语言和明确偏好可以按键精确读取；历史案例才可能需要语义检索。为了查一个已知字段而引入向量搜索，会增加不必要的不确定性。

在应用设计中，用户、租户和任务的身份应来自认证上下文，而不是模型生成的参数。检索前执行范围过滤，不能先全库召回再希望模型不泄露其他用户的数据。

删除操作还要覆盖摘要、向量索引和缓存等派生副本；备份保留策略则应独立说明。这里只提出工程检查项，不代替具体业务的隐私合规评估。

## 用什么测试判断记忆可用

我会至少设计六组场景：跨轮追问保留预算；用户改口覆盖旧偏好；两个用户相同问题互不串记忆；进程重启后恢复已完成步骤；过期工具结果触发刷新；删除偏好后不再被注入上下文。

另外应测试摘要是否丢掉“不”“仅本次”“日期待定”等关键限定。记忆系统的价值不是“记住最多”，而是让必要信息在正确范围内、以正确状态被取回。

本篇给出的是根据学习笔记整理的设计方法，没有将这些检查项描述为已经完成的生产部署。
