内容审核最容易混淆的两个结果是“没有发现候选”和“必要通道没有完成”。前者只是检测结果，后者是执行问题。一个可复核的系统，需要同时保存内容证据、处理范围和判定依据，不能只返回模型生成的一句结论。

## 候选发现不直接等于判定

可把流程分成四层：

```text
原始内容与位置
  → 确定性检测 / 语义检测 / 视觉检测
  → 候选与证据校验
  → 依据冻结的业务规则复核
  → 确认 / 排除 / 待人工处理
```

确定性规则负责明确模式，语义模型处理上下文，视觉模型观察画面与时序。多路命中可以合并证据，但不是多数投票；某一路缺失也不能通过其他两路一致而被忽略。

这里讨论的是审核工程结构，不提供特定法律或平台规则。规则来源、适用范围和版本应由业务审核流程独立维护，模型不能自行发明规则。

## 标准化后仍要能回到原文

保留不可变原文，再建立用于检测的标准化视图。Unicode 规范化、大小写转换和空白处理可能改变长度，因此标准化字符位置不能直接当作原文位置。[Python Unicode 规范化说明](https://docs.python.org/3/library/unicodedata.html#unicodedata.normalize)

位置映射应覆盖字符合并、展开和删除等情况，最终证据从原文截取，并记录映射策略版本。若实现只能可靠处理有限转换，就限制转换范围；不能靠逐字符规范化假定等同于整段规范化。

检测切分也要保留上下文。语义分块可按句段切分并重叠；重复候选按原始位置合并，而不是删除所有相同文字，因为同一句话出现在不同位置仍可能具有不同上下文。

## 图片证据保留原图坐标

全图理解适合发现场景，局部裁剪适合复核小字或小对象。证据应记录原始资产摘要、原图宽高、区域坐标，以及缩放、旋转和裁剪变换，避免把推理图上的坐标直接当成原图坐标。

OCR 文本与视觉观察应分开保留。模型的自由描述可能省略位置，也可能混入推断；最终复核应回看对应原图区域，而不是把描述当作原始事实。

## 视频需要时间与采样清单

视频同时包含语音、帧中文字、静态对象和时序行为。镜头边界采样、间隔采样与片段观察各有用途，组合也不能理论上保证零漏检。

记录采样时间点、片段窗口、未处理区间和模型版本；每个候选附原视频时间范围，必要时同时附画面区域。ASR 和字幕对齐也有语言、重叠语音和无法对齐字符等限制，不应把自动时间戳视为精确真值。[WhisperX 项目限制](https://github.com/m-bain/whisperX#limitations-)

所谓“覆盖完整”，只能表示完成了配置要求的处理范围，不等于看到了所有帧、更不等于发现了所有风险。

## 合法空结果与失败分开

| 情况 | 结果解释 |
| --- | --- |
| 成功解封装且无音轨 | 语音通道不适用或合法空结果 |
| OCR 成功但没有识别文字 | 本次检测未发现文字 |
| 必要模型超时或输出损坏 | 执行失败，不能按通过处理 |
| 证据位置越界或引用不存在 | 候选无效，需复核或失败处理 |
| 必要片段未处理 | 覆盖不完整 |

具体哪些通道是必需项，应由场景配置决定，并随任务保存快照。不能让模型在执行后自行把失败通道改成非必需。

## 受约束复核与评测

需要补充证据时，复核 Agent 只能调用允许的检索、原文定位或媒体查看工具，并受步骤和时间预算限制。证据仍不足时进入待处理状态，不把“未找到依据”自动解释为通过。

评测应分别检查候选召回、误报、证据位置正确性、覆盖失败率和人工复核负担，并按文字、图片、视频分层统计。模型给出的置信度不是天然校准的业务风险概率，不适合单独决定是否跳过复核。
