把素材 API 包装成 MCP 工具，不只是给方法补一份描述。模型会组合查询、详情和写入操作，因此每个工具都需要说明数据范围、结果状态和失败后的恢复方式。以下使用通用教学契约，不对应某个服务的真实接口。

## 按结果责任拆分工具

| 工具责任 | 返回内容 | 边界 |
| --- | --- | --- |
| 搜索素材 | 少量候选、分页游标 | 搜索命中不代表完整详情 |
| 读取详情 | 稳定 ID、媒体属性、分析状态 | 分析未完成不应伪装为空分析 |
| 获取访问链接 | 当前可用链接与失效信息 | 链接不是长期素材身份 |
| 提交导入 | 任务 ID 与接收状态 | 接收不等于入库完成 |
| 查询任务 | 阶段、结果或失败原因 | 必须检查任务归属 |

单条和批量操作可以分开定义，以减少参数歧义；但拆分不是越多越好，应让模型能从名称和输入判断操作结果。

## 搜索过滤不能授予权限

`project_id`、标签或“个人素材”等过滤条件，只能缩小已获授权的数据集合。不能让模型通过选择 `user_id`、租户或任意请求头来决定自己是谁。

服务端应从可信认证上下文取得调用者，再验证项目成员关系和资产归属。搜索、详情、任务查询和下载链接都要执行授权，不能只保护列表接口。具备读取权限，也不自动具备导入、修改或公开分享权限。

MCP 的安全文档强调令牌受众校验与禁止令牌透传等边界；工具接入协议不替代下游业务授权。[MCP 安全最佳实践](https://modelcontextprotocol.io/docs/tutorials/security/security_best_practices)

## 用稳定身份引用素材

以下是应用层结果示意，不是 MCP 协议规定的响应结构。

```json
{
  "asset_id": "example-asset",
  "media_type": "video",
  "duration_ms": 12000,
  "analysis_status": "pending",
  "analysis": null
}
```

把分析状态独立列出，可以区分尚未分析、成功但没有发现，以及失败。临时访问链接按需取得，并避免写入长期提示词、日志或任务快照；签名链接本身可能携带访问能力。

## 幂等键必须绑定调用语义

写入请求可用“调用者、操作、幂等键”确定唯一记录，并保存规范化参数的摘要。同键且同参数返回既有任务；同键但参数不同应返回明确冲突，而不是默默执行新操作。

并发时需要数据库唯一约束或等效原子机制。先查后写的普通代码检查，会让两个请求都认为自己是第一次。幂等记录还应规定有效期，以及处理中、失败和结果过期时的行为。

幂等键不会自动消除外部副作用。若远端不支持幂等且提交响应丢失，需查询对账或人工处理不确定状态，不能仅凭本地表中没有结果就再次上传。

## URL 导入扩大了网络边界

远程导入会让服务端替调用者发起网络请求，带来 SSRF 风险。应按业务建立来源允许范围，处理 URL 规范化、DNS 解析、私网与保留地址、重定向和实际连接目的地，并通过网络出口控制补足应用校验。

只检查域名文本或禁止 IP 字面量不足以防止 DNS 重绑定；自动跟随跳转也可能离开最初允许的来源。[OWASP SSRF 防护指南](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)

文件校验还要包含实际读取字节上限、超时、媒体解码与资源限制。扩展名、`Content-Type` 或 HEAD 返回的大小都只是输入信息，不能代替对实际内容的检查。

## 失败返回可恢复信息

错误应区分参数无效、权限拒绝、资源不存在、限流和外部服务失败，并给出脱敏原因与是否适合重试。模型可以据此修改输入或等待，但不能因为重试就扩大权限。

记录调用者、请求 ID、工具名、任务 ID 和结果状态，避免记录凭据或完整签名链接。一个可靠的工具契约，让调用者知道“现在完成了什么”，也知道“还需要查什么才能确认完成”。
